# A. 产品需求文档（PRD）

> 版本：v0.1.0 · 2026-11-08 · 状态：基线草案，待用户确认
> 上游：需求原文（产品名：界序 INTERFACE）+ 用户基调修正

## 1. 背景与定位

### 1.1 现状问题

| 问题 | 具体表现 |
|---|---|
| 灵感不可检索 | 收藏在 Dribbble/Behance/CodePen/GitHub/截图里，找不到、比不了 |
| 规格不可复用 | 只有效果图，没有时长、缓动、层级、阴影、Token；交给编程 Agent 时信息丢失 |
| 真假难辨 | AI 看图猜出来的参数与真实代码参数混在一起，无法追溯 |
| 预览不真实 | 素材库只放图片或 GIF，不能调参、不能切视口、不能切状态 |
| 服务依赖 | 云端素材库断网即废；工作流被服务可用性绑架 |

### 1.2 产品定位

**一间双主题的深色实验室，不是素材展厅。**

价值不在「收集量」，而在「可验证的规格化」：每个案例的关键参数都带来源与置信度，能直接变成设计规范或给编程 Agent 的提示词。

### 1.3 设计立场（硬约束）

1. 双主题对等：跟随系统 / 深色 / 浅色三态，**默认跟随系统**；深色是推荐工作场景，不是默认值。
2. 风格与主题分工：风格答「长什么样」，主题答「同一套界面怎么换皮」。
3. 组件分两层：atoms（单个控件）与 patterns（成组、带位置、带生命周期）。
4. 一案例一主域：组件答「长什么样、在哪」，反馈答「什么触发什么回应」，动效答「怎么过渡」。
5. 详情以预览为核心，不是大图 + 文案。
6. 置信度四态：`verified / estimated / user_defined / unknown`。

## 2. 用户与场景

| 角色 | 目标 | 关键路径 |
|---|---|---|
| 产品/UI 设计师 | 找参考、比较双主题、导出规范 | 左栏/条带浏览 → 详情双快照 → 收藏 → 导出 |
| 前端工程师 | 拿到真实可调参数 | 详情 → 调时长/缓动/距离 → 复制 CSS 提示词 |
| AI Agent 使用者 | 把案例变成实现指令 | 详情 → 提示词页签 → 选技术栈 → 复制 |
| 知识库维护者 | 持续补充、审核、去重 | AI 发现 → 待审核 → 修改 → 入库 |

### 2.1 核心 Job Stories

- 当我在做一个桌面工具时，我想快速看到「侧边栏展开」的真实参数，以便直接实现而不是反复试。
- 当我在定设计语言时，我想并排看同一风格的 light/dark，以便确认浅色不是脏灰。
- 当我收集了一堆案例后，我想用清单表格逐条核对来源、置信度与审核状态，以便清理低质量条目。
- 当 AI 给出一堆候选时，我想先审核再入库，以便不让推测值污染知识库。

## 3. 范围

### 3.1 V1 范围

- Windows 10/11 桌面应用；本地 SQLite 知识库。
- 5 个内容域（Theme 待确认）或 4 个已确认域；3 个工具位。
- 案例 CRUD、搜索、筛选、收藏、最近、导入、软删除、备份导出。
- 双主题 Token 系统；网格 + 表格视图；底部类型条带。
- 预览引擎：播放控制与参数调节真实生效。
- 提示词生成与导出。
- AI 分析（图/视频/网页/本地 HTML）与可插拔 Provider。
- AI 发现（搜索 Provider、抓取、去重、待审核）。
- **强制审核**：一切外部来源只能进候选池，必须人工确认后才进正式库；无免审开关。
- **导出双格式**：Markdown + JSON，一次操作同时产出，内容一致。

### 3.2 明确不做

账号/云同步/协作/社区；移动端；向量检索（只留接口不实现）；macOS 发布；绕过访问控制；未经授权再分发内容；无功能假按钮；假数据冒充功能。

### 3.3 库内容来源与合规边界（已定）

| 来源 | 是否随安装包分发 | 说明 |
|---|---|---|
| 框架与自绘示例 | 是 | 仅框架、自绘演示案例与必要元数据 |
| 用户导入 | 否 | 本地存储与展示，用户自行确认权利 |
| AI 采集候选 | 否 | 联网采集后进入候选池，人工审核后进库 |
| 官方后续内容包（如发布） | 可选 | **只允许自绘演示与元数据，不得包含第三方截图或录屏** |

- 安装包**不含知识库内容**；首装库为空，通过联网采集、用户导入与 AI 候选逐步填充。
- 任何外部来源都必须经过候选池与人工审核；不存在「定时任务免审」设置。
- 官方内容包若发布，必须沿用同一许可与素材登记口径，不得夹带第三方作品。

## 4. 信息架构

### 4.1 一级导航（推荐，待确认）

- 内容域：**风格 / 动效 / 交互反馈 / 组件 / 主题（候选）**
- 工具位：**AI 工作台 / AI 发现 / 设置**
- 库默认视图：进入知识库的落地页（合并原「首页」与「知识库管理」）
- 左栏底部：**我的收藏 / 最近使用**（视图，不是分类）

### 4.2 路由建议

```
/library            库默认视图（统计 + 最近 + 待审核入口）
/style /motion /feedback /components  （/theme 待确认）
/ai-studio /discovery /settings
/collections /recent
/case/:id
```

### 4.3 筛选与视图

- 唯一类型状态 `activeType`，左栏与底部条带双向同步（见 D-018）。
- 细化条件：平台、审核状态、来源类型、置信度、是否有双快照、组件层（atoms/patterns）。
- 视图：网格（默认）/ 表格（清单核对）。
- 排序：最新添加、最近浏览、收藏最多、最常使用、名称。

## 6. 置信度体系（核心）

### 6.1 定义

| 级别 | 含义 | 允许来源 |
|---|---|---|
| `verified` | 有可靠原始参数 | 原始 CSS/代码/官方规范；用户实测 |
| `estimated` | 根据素材推测 | AI 视觉/视频分析 |
| `user_defined` | 用户手动设置 | 用户编辑 |
| `unknown` | 无法判断 | 默认值 |

### 6.2 规则

- AI 管道不得输出 `verified`；发现即拒绝该字段的 verified 标记。
- 每个关键参数独立标记，不允许案例级一个布尔值代表全部。
- UI 必须常显芯片；导出必须保留；筛选可按置信度。
- 修改参数后，该字段自动变为 `user_defined`（保留原值作为证据可选）。

## 7. 非功能需求

| 项 | 目标 |
|---|---|
| 启动 | 冷启动 ≤ 2.5s（目标值，Phase 7 校准） |
| 列表 | 200 张卡片滚动 ≥ 55fps（目标值） |
| 内存 | 空闲 ≤ 250MB（目标值） |
| 离线 | AI/搜索未配置或断网时知识库 100% 可用 |
| 数据安全 | 备份导出可用；软删除可恢复；密钥不落库 |
| 可访问性 | 键盘可达、对比度达标、reduced-motion 支持 |
| 双主题 | 每个界面两套主题均验收 |

## 8. 成功指标

1. 首次启动 60 秒内可完成「导入一条案例 → 查看详情 → 调参 → 收藏」。
2. 任一案例详情能在 2 次点击内看到置信度来源。
3. 100 条案例下搜索结果首屏 ≤ 300ms。
4. 断网状态下无阻断性错误。
5. 双主题截图检查无对比度失败项。

## 9. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 单主表 JSON 查询弱 | 筛选慢 | 冗余列 + 索引 + FTS5 |
| 预览沙箱逃逸 | 安全 | 不开 same-origin；CSP；本地协议白名单 |
