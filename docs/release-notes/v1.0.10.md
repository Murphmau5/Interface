# v1.0.10 — 内置案例库

**发布类型**：内容发布版（安装包内置案例库 + 升级保护）
**适用平台**：Windows 10 1803+ / Windows 11（x64）

## 版本亮点

1.0.9 之前的版本装完是空库，用户要自己导入内容包才有东西看。这一版把案例库 V1 打进安装包：**装完首次启动就有 78 条案例、35 个类目**，打开即可浏览、筛选、预览。

### 1. 装完即有内容

- 内置内容包 `jiexu.v1.core`：风格 19 / 主题 6 / 组件 33 / 动效 10 / 反馈 10，共 78 条。
- 每条都有类目归属、可预览参数、专属提示词、程序化缩略图与对应渲染场景。
- 参数来源分四级标注：`verified` / `estimated` / `user_defined` / `unknown`；从总清单搬来的推断值保持 `estimated`，`verified` 为 0 条，没有把推断写成已验证。

### 2. 内置包与在线包分开

- 内置包只用于首次导入，导入成功即写入 `content_packages`（来源 `builtin`），视为已安装。
- 之后的更新走 `content.feedUrl` 在线包；安装包不会在每次启动时覆盖本地内容。
- 合并沿用既有规则：用户改过的条目不覆盖，用户删过的条目不复活，用户自建数据不动。

### 3. 升级不重复导入

- 启动时先查 `content_packages`：已存在同 id 包（包括此前手动导入的开发包）就整段跳过，不会出现第二份 78 条。
- 即使包记录缺失，导入也按包 id + 条目 id 定位已有案例，同 hash 计为 unchanged，不会新建重复行。

### 4. 触觉反馈不再留空组

- 类目表新增 `note` 字段；触觉反馈类目显示「暂缺，原因：Windows 桌面端无触觉通道」。
- 原因：Windows 桌面端没有可用的触觉 API，现有预览栈无法做出可看、可感的效果；条目留空但说明可见，不会被误认为加载失败。

## 需要 Key 才能用

本版没有新增需要 Key 的功能。AI 分析与联网搜索仍需在设置里配置 Key。

## 不配 Key / 没有服务器也能用

- 78 条内置案例的浏览、搜索、四维筛选、网格 / 表格切换
- 五类预览渲染与参数调节（含暂停 / 重播 / 循环 / 速度）
- 标签、收藏、合集、最近使用
- Markdown / JSON 导出、素材导入与 HTML 清洗预览
- 内容包本地导入 / 在线安装 / 卸载

## 验证范围

**已通过**：

- 静态门：`tsc --noEmit`、`eslint .`、`vite build`、许可证白名单。
- Rust 单测（含新增内置导入幂等用例）：67 通过、2 忽略。
- 全量预览审计（真实库，1440×900，浅色 / 深色各一轮）：83 条案例（含 5 条既有）缩略图齐全、场景主体高度占比 ≥82.2%、中心偏差 0、失败 0、控制台错误 0。
- 升级场景：真实库已有同 id 包记录（此前以 `local` 来源导入），与内置导入共用「已安装即跳过」判定；该判定由 Rust 单测覆盖，本版未在真实库上启动应用，避免测试改写用户数据。
- 全新库：临时数据目录用打包内资源连续导入两次 —— 首次 created 78，第二次 unchanged 78，无重复行；公钥仅走内置默认值，未依赖 `content.trustedKeys` 设置。

**未验证**：

- 真窗口交互（拖动、最小化、最大化、原生拖拽）未复测。
- 安装器只做静默覆盖安装验证；安装包未签名，首次运行仍可能出现 SmartScreen 提示。
- 仅 Windows x64；macOS 未验证。

## 已知限制

- 触觉反馈条目暂缺，等有可用触觉通道再补。
- 内置包签名使用开发密钥；后续在线包继续使用同一公钥，更换密钥需随版本更新内置公钥。
