# v1.0.16 — 内置内容包随软件升级

**发布类型**：修复版（内置包升级路径 + 参数口径修正）
**适用平台**：Windows 10 1803+ / Windows 11（x64）

## 为什么发这一版

1.0.15 上线了参数证据链，但内置内容包只要「装过」就跳过导入。结果是：全新安装的用户库里有 9 个参数级 `verified`，而从旧版本升级上来的用户，库里参数级 `verified` 仍然是 0——官方原文只写在内容源里，进不了已有数据库。

这一版把这条路径补上，同时把 Material 3 缓动的版本口径写准确。

### 1. 内置包比对版本后静默合并

启动时读取已装 `jiexu.v1.core` 的版本，与随包 zip 的 manifest 版本比较：

| 情况 | 行为 |
|---|---|
| 未安装 | 直接导入（与之前一致） |
| 随包版本更高 | 走合并路径：补齐新增、覆盖变更、保留用户改动与删除 |
| 版本相同或已装更高 | 不写入 |
| 用户手动卸载过 | 不装回 |

合并完成后不弹窗，只在「设置 → 内容包 → 已安装列表」留一条记录：

> 随软件更新到 v1.1.1（新增 0、更新 1、保留 0）

「保留」包含用户改过与删过的条目。用户之后自己重新导入该包，卸载标记会被清除，后续软件升级恢复合并。

### 2. 缓动版本口径改准

`style.material3.easing` 的 `specRef.version` 原写作「Expressive 2025+」，容易被读成 M3 现行值。官方已说明 Expressive 之后动效改用 spring（motion physics），旧的 duration / easing 体系标注 **no longer maintained**。现在写明：

> Pre-Expressive 旧 token（Expressive 起改用 spring；官方已标注 no longer maintained）

数值本身不变，仍是 M3 Standard `cubic-bezier(0.2, 0, 0, 1)`。

### 3. 老包兼容保持

内容包格式 1、格式 2 的导入单测全部保留并通过；缺 `specRef` 的 `verified` 仍在导入时降为 `estimated`。升版没有改动合并与降级规则。

## 验证范围

**已通过**：

- 用真实库（83 条）启动 1.0.16：内置包由 1.0.0 静默合并到 1.1.1，库中出现 **9 个参数级 `verified`**（8 个 `hitTarget` + `style.material3.easing`），`specRef` 五字段齐全；少一条字段都会在入库时被降级。
- 界面实测：点开参数来源，弹层显示平台与版本、组件、原文引句与「打开官方文档」；设置页已安装列表显示上述升级记录。
- Rust 单测 78 项（新增内置包升级、用户改动/删除保留、卸载不装回三组）。
- 无头回归 `spec-ref-check.mjs` 20/20。
- 静态门：`tsc --noEmit`、`eslint .`、`vite build`、许可证白名单。

**未验证**：

- 真窗口交互（标题栏拖动、双击最大化 / 还原、边缘吸附）未复测。
- 原生拖拽图片导入未复测。
- 安装器单屏交互未复测。
- 仅 Windows x64；macOS 未验证。
