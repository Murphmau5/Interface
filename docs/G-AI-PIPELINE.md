# G. AI 自动采集与案例分析流程

> 版本：v0.1.0 · 2026-11-08 · 状态：基线草案
> 目标：用户提供素材与 AI 主动发现两种入口，共享同一套「提取 → 分析 → 校验 → 去重 → 草稿 → 审核 → 入库」流程。

## 1. 两个入口，一条流水线

| 入口 | 起点 | 主要输入 |
|---|---|---|
| A. 用户提供素材 | AI 工作台 / 导入 | URL、图片、截图、GIF、MP4、本地 HTML、设计参考 |
| B. AI 主动发现 | AI 发现 | 自然语言需求 + 来源范围 + 目标数量 |

两者在 **S3 之后完全共用**；差异只在 S0–S2。

## 2. 阶段定义（S0–S11）

| 阶段 | 名称 | 输入 | 产出 | 责任模块 |
|---|---|---|---|---|
| S0 | 受理 | 用户素材/需求；或联网搜索候选项；或粘贴 URL | 任务记录（`ai_tasks` / `discovery_tasks` / `candidates`） | commands |
| S1 | 意图解析 | 自然语言需求 | 关键词、目标平台、目标分类、排除词；**网络候选须标注来源域名、作者、发现时间** | discovery/intent |
| S2 | URL 安全校验 | 候选 URL | 通过/拒绝（内网、非 http(s)、不支持） | security/url_guard |
| S3 | 抓取 | URL | HTML、响应头、状态码、截图（可选） | discovery/fetch |
| S4 | 提取 | HTML/截图 | 标题、OG、DOM 结构、CSS 变量、媒体清单、可见文本 | discovery/extract |
| S5 | 媒体采集 | 媒体清单/上传文件 | 缩略图、截图、GIF/视频引用；资产入库 | assets + security/file_guard |
| S6 | 多模态分析 | 截图/视频/网页文本 | 视觉、动效、交互三维结构化结果 | ai/provider |
| S7 | 校验与修复 | 原始 AI 输出 | 合法 payload + 置信度标记；失败则拒绝 | ai/schemas + repair |
| S8 | 去重 | payload + 元数据 | 重复/相似结论 | discovery/dedupe |
| S9 | 草稿生成 | 通过校验的结果 | 案例草稿 + 提示词草稿 + 关联建议 | discovery/draft |
| S10 | 待审核 | 草稿 / 网络候选 | `cases.status=pending_review` 或 `candidates.status=pending` | review |
| S11 | 入库 | 审核通过 | `status=approved` + FTS 索引 + 双主题快照；候选回填 `approved_case_id` | db/fts + preview/snapshot |

- **网络候选与正式库分表**：`search_network` 只写 `candidates`，不写 `cases`；`candidates_approve` 才进入 S9–S11。
- **禁止自动联网**：S0 的联网入口必须由 `Ctrl+Enter` 或用户点击「要不要联网找找？」触发。
- 未配置搜索 Key：S0 降级为「粘贴网址抓取该页面」，S2–S11 不变。

## 3. 状态机

```
queued
  → fetching        (S2–S3)
  → extracting      (S4–S5)
  → analyzing       (S6)
  → validating      (S7)
  → deduping        (S8)
  → drafting        (S9)
  → awaiting_review (S10)
  → approved        (S11)
  ↘ rejected        (用户在 S10 拒绝)
  ↘ duplicate       (S8 或人工标记重复)
  ↘ failed          (任一阶段不可恢复失败)
  ↘ canceled        (用户取消)
```

- `failed / canceled / duplicate` 保留任务与原始输出，便于诊断；不进入知识库。
- 状态转换必须写日志（含任务 id、阶段、耗时、错误码）。

## 4. 分阶段规则

### 4.1 S1 意图解析

- 输出：`SearchIntent { keywords[], platforms[], kinds[], avoid[], sourceScope[] }`。
- 若用户输入已含明确类型（如「侧边栏展开动画」），优先直接映射 kind，不额外发散。
- 关键词生成失败时不自行编造需求：回退为「原句关键词 + 去停用词」。

### 4.2 S2 URL 守卫（强制）

拒绝：非 http/https、内网/回环/链路本地、`localhost`、私有 IP、包含认证信息、非常规端口（除非白名单）。
重定向逐跳校验；DNS 解析后再校验一次，防 DNS rebinding。

### 4.3 S3 抓取

| 类型 | V1 行为 |
|---|---|
| 静态 HTML | `reqwest` 直接抓取，超时 30s |
| JS 渲染页面 | 默认**不自动渲染**；提示用户上传截图或启用可选 sidecar（待确认） |
| 需登录/验证码/付费墙 | 立即停止，记录 `blocked` 与原因，不尝试绕过 |
| 文件下载 | 仅下载白名单媒体类型，大小受限 |

User-Agent 明确标识；不伪造浏览器身份绕过限制。

### 4.4 S4 提取

- 元数据：`<title>`、OG、favicon、作者、发布时间。
- DOM：主要区块、组件候选、可交互元素清单（按钮/弹窗/导航）。
- CSS：颜色变量、圆角、阴影、字体、间距的启发式采样（只能 `estimated`）。
- 媒体：主图、演示 GIF/视频、代码片段（若页面公开提供）。
- 文本引用：只保存允许使用的摘要；不整站复制。

### 4.5 S5 媒体与版权

| 内容 | 处理 |
|---|---|
| 截图/缩略图 | 允许缓存并记录来源与抓取时间 |
| 原图/视频 | 默认只存链接与元数据；是否下载待确认（Q-10） |
| 代码片段 | 仅保存公开且许可允许的部分，标注来源 |
| 受限内容 | 只存元数据 + 链接 |

### 4.6 S6 分析维度

| 维度 | 提取内容 | 置信度 |
|---|---|---|
| 视觉 | 布局、层级、色彩、阴影、描边、圆角、字体、留白 | 颜色可来自 CSS → 有机会 `verified`；其余 `estimated` |
| 动效 | 类型、触发、方向、速度、距离、缓动、状态 | 从截图/视频只能 `estimated`；有原始 CSS/代码才可 `verified` |
| 交互 | 触发行为、初始/中间/最终状态、反馈、流程 | `estimated` / `unknown` |
| 分类 | kind、平台、风格、组件层、标签 | `estimated`，需人工确认 |
| 提示词 | 各目标技术栈草稿 | 由结构化结果生成，不是独立猜测 |

禁止：

- 从单张静态截图声称知道时长/缓动/触发。
- 把「看起来像 300ms」写成 `verified`。
- 用默认常见值填充未知字段。

### 4.7 S7 校验与修复

1. JSON 解析失败 → 拒绝（不猜测补全）。
2. Schema 校验失败 → 附带错误摘要修复 1 次。
3. 跨字段校验：`payload.kind == case.kind`；`componentLayer` 与 pattern/atom 互斥；patterns 必填 `patternMeta`。
4. 置信度校验：出现 `verified` 由 AI → 降级为 `estimated` + 警告。
5. 仍失败 → `E_AI_SCHEMA`，草稿不生成。

### 4.8 S8 去重

按顺序：

| 层 | 方法 | 命中处理 |
|---|---|---|
| L1 | `url_canonical` 完全相同 | 直接判重 |
| L2 | 缩略图 `sha256` 相同 | 判重 |
| L3 | 标题 + 域名 + 平台 高相似 | 标记「疑似重复」，人工确认 |
| L4 | payload 关键字段签名（kind + 主要分类 + 主要参数） | 标记「疑似相似」，人工确认 |
| L5（后续） | 向量相似度 | V1 不实现 |

- 同一发现任务内也去重，避免一次采到 5 个同款。
- 阈值暂定：标题相似 ≥ 0.85、payload 签名完全一致即疑似；**待 Phase 6 用真实样本校准**。
- 已存在于库且 `approved` 的 URL 默认跳过；用户可强制重新采集。

### 4.9 S9 草稿生成

草稿包含：

- `name`（含来源暗示，避免夸张营销词）
- `kind` + `componentLayer`（组件）
- `platforms`、`tags`、`description`
- `payload`（全部 `FieldClaim`）
- 提示词草稿（默认 `general` + `css`，用户可再生成）
- `relations` 建议（如组件 → 动效/反馈），只建议不自动写入
- `warnings`：能力边界、来源受限、疑似重复等

### 4.10 S10 审核

用户可执行：

- 确认入库（`approve`）
- 修改分类/描述/参数/提示词（`update_draft`）
- 拒绝（`reject`，记录原因）
- 标记重复（`duplicate`，关联到已有案例）
- 加入收藏（入库后）
- 删除草稿（软删除）

规则：

- **强制人工审核，无免审开关**：一切外部来源（链接抓取、AI 发现、定时补充）只能进入候选池，必须人工确认后才进正式库；不存在关闭审核的设置项。
- 审核界面必须显著展示置信度分布与「AI 推测」标记。
- 未审核草稿不进入默认知识库列表、不参与「最近添加」正式统计。

### 4.11 S11 入库

- 事务写 `cases` + `assets` + `prompts` + `source` + `case_history`。
- 生成 FTS 索引。
- 双主题快照：风格/主题案例必须生成 light/dark 两张快照；失败则入库但标记 `snapshot_missing`。
- 通知 UI 刷新。

## 5. 取消、失败与重试

| 事件 | 行为 |
|---|---|
| 用户取消 | 在检查点停止；保留已完成产物为草稿或丢弃（按设置） |
| 网络失败 | 重试 2 次（指数退避）；仍失败 → `failed`，记录 URL 与错误码 |
| AI 限流 | 退避重试 2 次；仍失败 → `failed`，可整体重跑 |
| AI 超时 | 重试 1 次 |
| Schema 失败 | 修复 1 次，不重发原请求 |
| 单条失败 | 不影响同任务其他候选；任务汇总 `failed_count` |
| 全部失败 | 任务 `failed`，保留失败原因列表 |

检查点：S2 后、S3 前后、S6 前、S7 后、S9 前、S11 前。

## 6. 限额与预算

| 项 | 默认 | 可配 |
|---|---|---|
| 单次发现候选数 | 10 | 1–30 |
| 单任务分析并发 | 2 | 1–4 |
| 单文件大小 | 图片 10MB / 视频 200MB | 是 |
| 单案例素材总量 | 500MB | 是 |
| 视频抽帧 | 8–12 帧 | 是（若启用） |
| 单任务时长上限 | 10 分钟 | 是 |
| 搜索请求频率 | 1 req/s | 是 |

超限行为：拒绝并给出明确原因，不静默截断。

## 7. 「知识库自动补充」

- V1：**手动触发**一次补充任务（用户设定主题、分类、平台、来源、数量、是否生成提示词、是否需要审核）。
- 定时执行：V1 不做，预留 `discovery_tasks.schedule_json`。
- 自动补充必须：优先补知识库缺失类型、检查重复、避免重复采集同 URL、记录失败任务、可停止。

## 8. AI 设计组合

1. 用户选择多个案例（如：新拟态风格 + 玻璃弹窗 + 共享元素过渡 + 弹性按钮反馈）。
2. 抽取各案例的结构化参数（只读，不改原案例）。
3. 检测冲突：材质冲突（新拟态 vs 玻璃）、阴影/描边规则冲突、动效时长体系不一致、双主题策略冲突。
4. 输出统一规范 + 冲突说明 + 推荐取舍；不自动覆盖任何原案例。
5. 结果可作为新草稿保存（kind 由用户选择，通常为 `style` 或 `design_spec` 提示词）。

## 9. 提示词生成

- 输入：案例结构化 payload + 目标技术栈 + 目标 Agent + 双主题要求。
- 输出必须包含：设计目标、视觉风格、组件结构、交互行为、动效参数、响应式规则、深色/浅色、实现约束、验收标准。
- 每个参数保留置信度标注，例如 `duration: 420ms (estimated — AI 推测，请实测校准)`。
- 支持复制、编辑、保存、Markdown/JSON 导出。

## 10. 安全与合规红线

1. 不绕过访问控制、验证码、付费墙。
2. 不将受限内容下载并再分发。
3. 外部内容不进入系统指令层（防提示词注入）。
4. 不执行页面脚本；预览与分析分离。
5. 来源与权限信息必须随案例保存，可追溯。
6. 用户可一键删除采集结果与素材。

## 11. 可观测性

- 每个任务记录：阶段耗时、候选数、成功/重复/失败数、错误码分布、模型与 token 估算。
- 开发期报告写 `.agent/reports/`；应用运行日志写 appData `logs/`。
- 不记录密钥、完整页面正文超过必要范围的内容、用户隐私。
